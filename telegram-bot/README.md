# EclipseIsland — Telegram-бот

Python 3.11+, только стандартная библиотека. Канал: @EclipseIsland. Админ: 1375098087. Встроенных токенов нет.

1. Замени ранее раскрытый токен через @BotFather /revoke.
2. Добавь бота администратором канала @EclipseIsland.
3. Сначала загрузи исходники приложения в публичный GitHub-репозиторий и запусти первый выпуск Actions → Publish EclipseIsland → Run workflow → 0.9.0. Инструкция — START-HERE.md в архиве исходников.
4. Создай fine-grained GitHub token для выбранного репозитория: Actions read/write, Contents read.
5. Скопируй .env.example в .env. Заполни BOT_TOKEN, GITHUB_REPO и GITHUB_TOKEN. Остальные значения уже подготовлены.
6. Запусти `docker compose up -d --build`. Логи: `docker compose logs -f --tail=50`.
7. Открой /start, проверь подписку и получение Setup. /admin доступна только владельцу с заданным ID.

Без Docker: задай переменные из .env.example в панели хостинга, команда `python bot.py`. Либо с заполненным .env запусти `python run.py`. pip-пакеты не нужны. Порт и домен не требуются: используется long polling. Нужен постоянно работающий процесс с доступом к api.telegram.org, api.github.com и файлам GitHub Releases. Запускай одну копию.

Если существует webhook, останови старый сервис и выполни `python run.py --clear-webhook` или `docker compose run --rm bot python /app/bot.py --clear-webhook`.

Новое обновление: сначала git push изменений в main, затем /admin → Выпустить обновление → новый номер (например 0.9.1) → описание → подтверждение. Бот запускает release.yml и отслеживает результат. Доступным выпуск становится после успешной сборки/публикации; пользователи нового Setup получат его при следующем запуске через ярлык. Изменения кода бот не придумывает и не загружает.

Кнопка «Проверить настройку» показывает права бота и текущий выпуск. «Статус сборок» содержит ссылку на GitHub Actions. Если после сбоя остался draft release, удали его в GitHub либо выбери следующий номер версии.

Храни .env и data/ приватно. Делай резервную копию data/ или Docker volume. data/ хранит SQLite с очередью, пользователями и состояниями, setup-cache — только кеш последнего Setup. Секреты не записываются в базу. При истечении GitHub token обнови .env и пересоздай контейнер: `docker compose up -d --force-recreate`.

Подписка проверяется при каждой выдаче через getChatMember. При ошибке проверки Setup не выдаётся. Публичный GitHub и уже полученный Setup доступны по прямой ссылке: это не DRM и не запрет пересылки.

Проверки: `python -m unittest -v`.
