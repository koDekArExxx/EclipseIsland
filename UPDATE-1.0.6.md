# EclipseIsland 1.0.6 — подключение погоды

В 1.0.5 два адреса вели к одному сервису wttr.in. Если он был недоступен, полноценного независимого резерва не было.

- Добавлены три независимых источника: MET Norway, Open-Meteo и wttr.in. Используется первый корректный ответ, ненужные запросы отменяются. Общая сетевая попытка ограничена таймаутом, а не последовательным ожиданием каждого провайдера.
- Для MET используется идентифицирующий User-Agent и учитывается серверный Expires. Погодные данные другого источника не подписываются именем MET или wttr.
- Системный сетевой путь Electron дополнен резервным Node-запросом при ошибке транспорта. Встроенного VPN нет.
- Успешные ответы сохраняются в weather-cache.json в профиле приложения и могут восстановиться после перезапуска. Устаревшие данные помечаются, данные другого города не подставляются. Испорченный кэш пропускается.
- Ошибка показывает источники и тип сбоя. Температура «ощущается» скрыта, если источник её не передал. Диапазон MET подписывается как ближайшие 24 часа.
- Встроенный поиск российских городов и предыдущие исправления приложения сохранены.

## Выпуск

Распакуйте архив поверх исходников с заменой файлов. Это исходники исправления, Windows Setup создаётся при выпуске через бота.

```powershell
git add .
git commit -m "EclipseIsland 1.0.6"
git pull --rebase origin main
git push origin main
```

После успешной отправки: бот → Выпустить обновление → `1.0.6`.

## Проверка

198 JS-тестов прошли. Проверены блокировка отдельных провайдеров, зависший запрос, отмена проигравшего запроса, кэш после перезапуска, атомарное сохранение, Expires, резерв транспорта, разбор ответа MET, локальный поиск, подпись источника и отсутствие выдуманной ощущаемой температуры.

В живом запросе новый клиент получил погоду для Москвы, Санкт-Петербурга и Казани. В этом прогоне первым ответил Open-Meteo. Отдельно проверен сценарий, когда wttr и Open-Meteo заблокированы, а корректные данные отдаёт MET. Последний сценарий воспроизводился тестовыми отказами; доступность на конкретном российском провайдере не проверялась.

После установки проверьте Москву без VPN на целевом ПК. Если данные не появились, сохраните полный текст ошибки: он теперь показывает, какие источники отказали. Одного публичного сервиса, гарантированно доступного в каждой сети, нет; три источника и кэш уменьшают зависимость от конкретного сервиса, но не отменяют сетевые ограничения.
