# EclipseIsland 0.9.0 — запуск и публикация

## 1. Сначала замени токен Telegram

Переданный в чат токен не включён в проект. В @BotFather используй /revoke для своего бота и получи новый токен. Новый токен вводи только в окружении хостинга или в локальном файле telegram-bot/.env. Не загружай его в GitHub.

## 2. Создай GitHub-репозиторий

На https://github.com/new создай **Public** репозиторий `EclipseIsland`. Оставь его пустым: не добавляй README, .gitignore и лицензию через сайт. Приложению нужен публичный доступ к выпускам без токенов пользователей.

Распакуй архив исходников, открой папку EclipseIsland в VS Code. В корне должны быть package.json, src, electron, distribution, telegram-bot и **.github/workflows/release.yml**. Папка .github обязательно нужна.

В терминале VS Code выполни, заменив YOUR_LOGIN на свой логин GitHub:

```powershell
git init
git add .
git commit -m "EclipseIsland 0.9.0"
git branch -M main
git remote add origin https://github.com/YOUR_LOGIN/EclipseIsland.git
git push -u origin main
```

При первом использовании Git попросит имя/почту: задай `git config --global user.name "Твоё имя"` и `git config --global user.email "Твоя почта"`, затем повтори commit. Для входа используй окно авторизации Git/GitHub; секреты в команды вставлять не нужно. Если Git не установлен, установи Git for Windows и перезапусти VS Code.

## 3. Получи первый Setup

Открой репозиторий → **Actions → Publish EclipseIsland → Run workflow**. Ветка main, версия **0.9.0**, описание по желанию. Если Actions предлагает включить workflows, включи их.

GitHub сам проверит проект, соберёт Windows x64 и опубликует выпуск. Дождись зелёной сборки. В разделе **Releases** появятся:

| Файл | Назначение |
| --- | --- |
| EclipseIsland-Setup.exe | Маленький установщик и постоянный загрузчик обновлений |
| EclipseIsland-app.zip | Полная программа, скачивается установщиком |
| update-manifest.json | Версия, размер и SHA-256 для загрузчика |

Не переименовывай эти три файла. Не редактируй manifest вручную. Setup в этом архиве исходников не приложен: ему нужен адрес именно твоего репозитория; Actions встроит его автоматически. Тестовая компиляция загрузчика с иконкой весит около 101 КиБ; точный размер итогового EXE покажет сборка.

Для первой проверки закрой старый островок через трей, скачай Setup из своего Release и запусти. После установки запускай островок через новый ярлык EclipseIsland. Старый установщик/старый EXE не поддерживает эту схему обновления.

## 4. Подготовь бота

Добавь своего бота **администратором** в канал https://t.me/EclipseIsland. Это требуется Telegram для надёжной проверки подписки других пользователей. Бот не публикует посты в канале; права публикации ему для работы не нужны.

На GitHub открой **Settings своего аккаунта → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**. Выбери только репозиторий EclipseIsland и права:

- **Actions: Read and write** — запуск и наблюдение сборок;
- **Contents: Read-only** — чтение выпусков;
- Metadata: Read-only добавится автоматически.

Укажи срок действия токена и обновляй его на хостинге до истечения. Этот токен хранится только у бота. GitHub Actions публикует релиз своим встроенным временным токеном; дополнительные Repository secrets для этого проекта не нужны.

## 5. Запусти бота на хостинге

Нужен хостинг с постоянным Python-процессом или Docker. Статический хостинг и функции, засыпающие после запроса, не подходят для long polling. Веб-домен, HTTPS-сертификат и открытый входящий порт боту не нужны; нужен исходящий интернет к Telegram/GitHub. Запускай только одну копию бота с одним BOT_TOKEN.

Распакуй отдельный архив EclipseIsland-TelegramBot на сервер. Скопируй `.env.example` в `.env` и открой файл:

```dotenv
BOT_TOKEN=НОВЫЙ_ТОКЕН_ИЗ_BOTFATHER
ADMIN_ID=1375098087
CHANNEL_ID=@EclipseIsland
CHANNEL_URL=https://t.me/EclipseIsland
GITHUB_REPO=YOUR_LOGIN/EclipseIsland
GITHUB_TOKEN=ТОКЕН_GITHUB_ИЗ_ШАГА_4
GITHUB_REF=main
DATA_DIR=./data
```

Не добавляй кавычки и не меняй ADMIN_ID. Настоящий .env не передавай людям. Сохраняй резервную копию data/ или Docker volume: там очередь выпусков, состояния диалога и пользователи.

**Docker Compose:**

```sh
cp .env.example .env
# Заполни .env в редакторе, затем:
docker compose up -d --build
docker compose logs -f --tail=50
```

**Хостинг с Python:** Python 3.11 или новее, установка pip-пакетов не нужна. В панели хостинга задай переменные из .env.example, рабочую папку с bot.py и команду `python bot.py`. Сам bot.py файл .env не читает: его читает Compose либо переменные задаются в панели хоста. Для запуска с локальным .env и Python 3.11+ можно использовать `python run.py`.

Если бот сообщает о существующем webhook, останови прежний сервис и один раз выполни `python bot.py --clear-webhook` в окружении с заданными переменными. Для .env используй `python run.py --clear-webhook`. В Docker: `docker compose run --rm bot python /app/bot.py --clear-webhook`, затем `docker compose up -d`.

Теперь открой бота: **/start → подписаться → Получить установщик**. Из аккаунта с ID 1375098087 доступна **/admin → Проверить настройку**. Пользователь, отписавшийся от канала, не сможет повторно получить Setup через бота. Это проверка выдачи в боте: публичные GitHub-файлы и уже скачанный Setup можно пересылать, защита доступа внутри приложения не добавлена.

## 6. Как выпускать обновления

Сначала внеси изменения в приложение и загрузи их в main:

```powershell
git add .
git commit -m "Описание исправлений"
git push
```

Затем в Telegram: **/admin → Выпустить обновление → 0.9.1 → описание → подтвердить**. Для следующего выпуска укажи 0.9.2 и так далее. Бот запускает сборку исходников из main; он сам не меняет код. Номер в package.json для этой сборки Actions подставляет автоматически.

Бот сообщит результат. Пока сборка не прошла, пользователи получают предыдущую версию. При успехе новый выпуск появится в Releases, а пользователи нового Setup получат его при следующем запуске через ярлык/автозагрузку. Во время текущей записи приложение принудительно не закрывается. Для обновления уже работающий островок нужно завершить через трей и запустить снова.

Перед каждым запуском загрузчик проверяет выпуск. Если обновления нет — запускает установленную программу. Если есть — скачивает, проверяет SHA-256, распаковывает отдельно, переключает версию и запускает. При недоступном интернете запускается установленная копия. При ошибке загрузки сохраняется последняя рабочая версия. При обнаруженном раннем аварийном завершении новой программы загрузчик пробует предыдущую; это проверка раннего запуска, не гарантия отсутствия ошибок при дальнейшем использовании.

Хранятся текущая и одна предыдущая версия для восстановления. Настройки остаются в `%APPDATA%\EclipseIsland`; записи/снимки не удаляются. Удаление программы доступно в настройках приложений Windows. При установке поверх старой отдельной NSIS-версии сначала закрой и при необходимости удали её, чтобы не осталось двух ярлыков.

## 7. Запуск из исходников в VS Code

Windows 10 22H2/11 x64, Node.js 22.22.2+ (ветка 22), .NET 10 SDK. В тонком архиве нет готовых нативных библиотек: они собираются из native/.

```powershell
npm.cmd ci
npm.cmd run build:media
npm.cmd test
npm.cmd start
```

Если нужен только веб-просмотр интерфейса: `npm.cmd run preview` (системные интеграции требуют Windows-приложения).

Чтобы собрать web Setup локально в PowerShell:

```powershell
$env:RELEASE_REPOSITORY="YOUR_LOGIN/EclipseIsland"
$env:RELEASE_VERSION="0.9.0"
npm.cmd run build:online
```

Результаты в release-online/. Локальная команда только создаёт файлы; для полноценного обновления все три нужно разместить в соответствующем публичном GitHub Release v0.9.0. Предпочтительнее автоматическая сборка Actions.

Обычный большой офлайн-установщик: сначала `npm.cmd run fetch:encoder`, затем `npm.cmd run dist:win`. Он не использует новый web-загрузчик и не получает автоматические обновления этим способом. Не распространяй его вместо маленького Setup, если нужны обновления.

## 8. Размер и производительность

- Удалён индикатор FPS и постоянный цикл requestAnimationFrame, который считал кадры.
- При изменении размера сохраняется выбранный материал: стекло не переключается на плотный фон. Вложенные элементы не пересчитывают отдельные backdrop-фильтры.
- Измерение границ при переходах объединено в один цикл, убраны дубли от ResizeObserver.
- Setup использует .NET Framework Windows и не несёт собственный runtime. Его маленький размер не означает такого же размера самой программы.
- Electron упакован в ASAR; включены только ru/en-US. Полный native-сервис нужен для системных музыкальных плееров и не удалён ради уменьшения размера.
- FFmpeg (~80 МБ распакованным) исключён из web-пакета и скачивается один раз при первом использовании записи/повтора, с проверкой SHA-256. Для первого запуска этих функций нужен интернет и время на загрузку. При ошибке функция показывает ошибку; можно повторить. При дальнейшем запуске используется локальный кеш.

Проверены автотесты приложения и бота, а также компиляция Windows-загрузчика. Его Windows-тесты входят в Actions. Реальная работа захвата, установки/отката и плавность поверх игры требуют проверки на Windows; на этой машине они не измерялись. Если игра занимает весь GPU, эти изменения не гарантируют конкретный FPS.

Загрузчик пока без подписи издателя; Windows может показать SmartScreen. Для публичного распространения сертификат подписи добавляется отдельно.

## Если что-то не сработало

- Actions красный: открой неуспешный шаг и скопируй текст ошибки. Бот показывает ссылку на запуск в «Статус сборок».
- После неудачной загрузки релиза может остаться draft: удали его в Releases либо используй следующий номер версии. Бот не перезаписывает существующие выпуски.
- Setup не скачивает: проверь публичность репозитория и наличие трёх файлов в опубликованном Release; VPN/антивирус/фильтры сети могут мешать GitHub.
- Бот не проверяет подписку: проверь, что он админ именно @EclipseIsland.
- Бот не выпускает обновление: проверь repo/ref, права и срок GITHUB_TOKEN, наличие release.yml в main.
- Telegram сообщает Conflict: запущены две копии или остался старый сервис; оставь одну.

Официальные справки: https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event и https://core.telegram.org/bots/api#getchatmember.
